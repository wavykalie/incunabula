# niche-pool.txt — the shelves roll-brief.py draws from.

# APPEND-ONLY, never reorder or delete: roll-brief.py re-derives old rolls from
# the first K lines (the brief records K). An edit to an old line rewrites history.
#
# This header is NOT part of that invariant — the dice skips #-comments, so it
# stays editable. Removing or reordering a NICHE line does not.
#
# One niche per line. The pool grows two ways.
#
# 1. Every autonomous firing appends FIVE new niches — invented by the run,
#    because a script can only draw a niche, never invent one. A pool that never
#    grows is a button that gives the same six answers forever.
#
# 2. niche-grow.py tops the pool up to a target in bulk. The flavour axis of a
#    shelf does not have to be imagined from nothing, so it crosses the
#    harvested Wikipedia concepts in tools/aesthetics-concepts.txt with genres,
#    settings and forms, randomly and from a printed seed:
#        python tools/niche-grow.py --target 1000 --seed 20261005 --dry-run
#    Growth 40 -> 1000 happened that way on 2026-10-05 (seed 20261005), was audited
#    the same day, and the grown region was rebuilt under a concept budget
#    (seed 20261006). Only the first 40 niches were ever protected: the one
#    published roll records pool-size 35, so nothing drawn beyond 35 exists to
#    be re-derived. The grower refuses to write if the result would remove or
#    reorder a niche that is already here.
