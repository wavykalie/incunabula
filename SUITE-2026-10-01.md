## The suite command (reusable)

The book list is READ, not typed. `check-registry.py` verifies BOOKS.yaml against
the disk in both directions first — the marrow-light omission above is the failure
this removes — and the loop consumes its `--paths` output:

    INC=incunabula/tools/prose
    bash $INC/verify-freeze.sh
    python $INC/../check-registry.py || exit 1     # registry must agree with disk
    # tr -d '\r': on Windows, python's stdout is text mode and appends CR to every
    # line. The tool strips it on its side too; this is the belt to that braces.
    for B in $(python $INC/../check-registry.py --paths | tr -d '\r'); do
      echo "### $B"
      for G in check-length check-uniformity check-drift check-arc check-surplus \
               check-recoverable check-names check-premise-distinct check-comps; do
        python $INC/$G.py "$B" >/dev/null 2>&1; echo "  $G rc=$?"
      done
      if [ -d "$B/manuscript/chapters" ]; then
        bash $INC/deslop-check.sh "$B/manuscript/chapters" >/dev/null 2>&1
        echo "  deslop rc=$?"
      fi
    done

New books enter the loop by being registered (`python incunabula/tools/init-book.py
--path ... --title ...`), never by editing a report.

Scope and inputs, for reading the codes:
- prose gates (L1, U, drift, arc, surplus, recoverable, deslop) need a drafted
  `manuscript/chapters/`; on a concept-stage book their failures are noise.
- `check-names` needs `CANON_LEDGER.yaml`; `check-premise-distinct` needs a
  `premise_axes` block; `check-comps` needs `research/market-research.md`. Exit 2 on
  a missing input is the gate asking for one, not a book failing.
- `check-length` exits: 0 in range, 1 outside it (a real failure), 2 no target
  declared, 3 ungoverned (no state file at the root). Exit 3 means someone must say
  which of "lost" and "deliberately ungoverned" it is.
